# Open Estimate Web保存を標準にしたフロー改善仕様案

> **2026-10-31改訂による位置づけ**：本書は2026-10-28当時の設計履歴です。読取チェック、開始カード必須、解析開始前の一括同意、三項目選択、およびそれを前提とするA01/A02/A14/A17等は、[SYSTEM-SPEC.md](SYSTEM-SPEC.md)と[ローカル利用体験と外部送信の確認](LOCAL-UX-AND-TRANSMISSION-SPEC.md)で置き換えました。新しい画面文言・受入条件は後者のLUX01〜LUX12を参照してください。証明・外部送信範囲・365日期限等の不変条件は維持します。旧本文と受入IDは履歴として残し、新仕様の合格に読み替えません。

作成日：2026-10-28。状態：実装指示書へ反映済みの設計背景。対象：ChatGPT上の見積体験、MCPの検証・証明、Web保存・公開、および旧フローの整理。実装の正本は[SYSTEM-SPEC.md](SYSTEM-SPEC.md)と[SYSTEM-IMPLEMENTATION-PLAN.md](SYSTEM-IMPLEMENTATION-PLAN.md)。

## 1 目標と変更の要点

利用者は解析開始前に、対象読取・検証送信・Web保存公開のうち希望する処理を一つの画面で承認する。承認範囲内の標準フローは途中で同意を求め直さず、証明付きの結果と公開URLまで進める。返されたURLを開くだけで結果を閲覧でき、同じURLを後日も利用できる。

標準フローは「対象範囲と全工程を提示 → 必要な同意を一画面で取得 → 算定 → チャット上の結果・PDF → 証明取得・Web保存 → 結果URL」とする。公開しない選択も残す。開始時点で公開機能までの全容を伝え、公開を選択した利用者にはURL取得まで進める。結果カードの表示を二度目の承認待ちにしない。

三つの処理系をつなぐ契約は構造化した見積データとする。Markdownは出力形式の一つであり、MCP送信やWeb登録のためにMarkdownファイルを作成・読取・選択する必要はない。

| 項目 | 改善後 |
|---|---|
| 同意の時点 | 解析開始前の一画面に集約。対象読取・検証送信・Web公開を項目別に選択 |
| 結果の表示 | ChatGPTの結果カード・本文・PDFを表示して続行。標準フローでは確認待ちにしない |
| 追加確認 | 当初承認の範囲を超える操作が必要になった場合だけ、差分を確認 |
| Webへの受渡し | パラメーターとしてデータを登録し、通常のHTTPS URLを返す |
| Web結果 | 保存済みの固定結果。URLを開くだけで閲覧可能 |
| 閲覧者のログイン | 不要 |
| Web公開期間 | 公開完了から1年間（365日）。15分・30日の段階と延長操作は廃止 |
| 証明対象 | 正規化した見積データ。MarkdownやHTMLの見た目に依存しない |
| 再試行 | 同じ入力・同じ操作IDで続行し、同じ証明・同じURLを返す |

本案の採用内容はSYSTEM-SPEC.mdとSYSTEM-IMPLEMENTATION-PLAN.mdへ反映した。仕様文書の更新は実装・本番反映の完了を意味しない。0.11.1の受入記録にある再同意修正は再利用し、ファイル選択式のWeb受渡しは新規フローから外す。

## 2 利用者に見せる標準フロー

### 2.1 開始と対象範囲の確認

最初に「対象と処理を選んで開始 → 見積・PDF → 検証・証明 → Web保存とURL」の全体像を示す。本文を読まない構成走査等で対象フォルダー・範囲・除外・取得上限を具体化した後、本文解析の前に一括確認する。対象読取と外部送信・公開は同意項目として区別するが、取得するタイミングは一つにまとめる。

案内文の基準は次のとおりとする。

> 以下の対象範囲を見積もり、結果とPDFをこのチャットに表示します。検証とWeb公開も選択すると、数値の検証・証明取得・Webへの保存公開まで続けて実行し、共有用URLをお渡しします。通常は途中の追加確認はありません。ソースコード・案件名・ローカルパス・判断根拠はOpen Estimateへ送りません。AI解析では、モデル提供元（OpenAI、Anthropicなど、利用中のAIサービスのモデル提供元のこと）で処理される場合があります。

Webや証明発行の設定不足だけで、対象確認・ローカル解析を停止しない。利用不可が判明している機能は開始時に明示する。

### 2.2 開始画面でまとめて取得する同意

対象範囲、実際のMCP送信先とWeb登録先、送信項目、公開範囲、保存方針を一画面に示し、次のチェック項目と開始ボタンを提供する。

- [ ] 表示された対象範囲のソースを読み取り、解析・見積することに同意します。
- [ ] 算定後の匿名の数値モデル・集計結果・計算条件・品質情報をOpen Estimateへ送り、検証・証明を取得することに同意します。
- [ ] 集計結果・計算条件・品質情報と証明をWebへ保存し、1年間公開することに同意します。URLはログインなしで閲覧・共有できます。公開終了後も、ダウンロードしたPDFは手元で利用できます。

主操作は「選択した内容で見積を開始する」。チェックは初期状態では未選択とし、チェックと開始操作をもって明示承認を記録する。対象読取は解析開始に必須、検証と公開は任意とする。Web公開には検証の選択が必要であり、公開だけが選ばれた場合はこの依存を同じ画面で示す。検証を解除した際に公開だけを残さず、未選択の項目を自動承認しない。

「ローカル見積のみ」「検証・証明まで」「Web公開まで」の三つの組合せを処理できる。初期画面に対応関係を示し、後から順に同じ同意を求めない。検証を選ばず公開も選ばなかった場合、数値モデルや見積由来のハッシュをOpen Estimateへ送らない。

開始時には算定値が未確定であること、承認した対象から算定した結果を承認した形式で送信・公開することを説明する。暫定・未確認・取得不足がある場合も、その品質区分と全体／部分の区別を付けた結果になることを明示する。品質区分の変化だけで毎回同意を取り直さない。

MCPだけへ送る項目とWebで公開する項目は区別し、「送信する項目の詳細」を展開できるようにする。算定後の実データも結果カードから参照可能とするが、閲覧や再承認を標準フローの待機条件にしない。後から発行される証明番号・日時等は種類と発行元を開始時に示し、承認範囲内の付加情報として扱う。

Intelligent UIのチェック項目と開始ボタンを標準とする。複数チェックを実装できないホストでは、同じ説明と三つの組合せを一度の選択で提示する。本文へ代替する場合も一度の回答で選択内容を確定し、項目ごとに質問を繰り返さない。カード表示や見積依頼だけでは承認済みにしない。

ホスト自身が要求する接続・操作確認は製品側の同意とは別であり、回避しない。接続設定やツールの説明を開始時の処理内容に合わせ、予見できる権限不足を可能な限り開始前に検出する。製品側の追加確認0回と、実ホストが出す確認回数は受入で別に記録する。

### 2.3 結果とPDFの提示

まず総工数の中央値を大きく示す。人日・参考幅・品質区分を続け、金額・機能規模・詳細条件は後に置く。チャット本文も、処理経過ではなく結論から始める。

主要ソース不足の場合は「全体工数：未算出」を主表示にし、取得済み部分の参考工数を別に示す。部分試算を公開する場合も、この区別をカード・PDF・Webで維持する。

固定した同一データからカード・本文・PDFを生成する。PDFは標準成果物とするが、PDF生成・取得の失敗は見積データを破棄せず、修復可能な別状態として扱う。Web公開にPDFファイルの添付は要求しない。

### 2.4 承認後と完了表示

ローカルの進行処理が、開始時に選ばれた処理だけを実行する。公開まで選ばれていれば、算定結果の表示に続けて、MCPでの証明取得、返却証明の検証、Web登録を進める。正常時の追加質問、ファイル選択、照合コード入力、Web上の再承認は設けない。結果カードに承認済み範囲と現在の処理を表示し、未送信処理の中止を可能にする。中止のための待ち時間や再承認ゲートは設けない。

完了表示は、工数の結論に続けて「見積結果をWebに保存・公開しました」と結果URL・公開終了日を示す。「結果を開く」「URLをコピー」「PDFを取得」を用意する。証明の範囲は結果ページから確認できる。

APIがURLを返した段階は公開保存完了であり、ブラウザーで実表示を確認したこととは区別する。通常のHTTPSリンクで到達可能にし、閲覧のためにPOSTやローカルファイルを要求しない。

公開を選んでいない場合は、選択した工程の完了を報告して終了する。後から検証・公開を希望した場合は、未承認の操作だけを一度確認し、解析からやり直さない。

## 3 三つの処理系の役割

| 処理系 | 担当 | 依存させないもの |
|---|---|---|
| ChatGPTローカル | 対話、取得・解析、算定、結果・PDF、承認、検証と登録の順次実行、再試行 | Webの内部DB・受付状態、発行秘密鍵 |
| MCP検証サービス | 版付きルール、数値検証、構造化結果への署名、最小発行記録 | Web保存の成否、公開URL、ブラウザー、利用者ログイン |
| Web保存・表示サービス | データ・証明の検査、保存、URL発行、表示、公開停止 | ソース、元run、Markdownファイル、数値再計算、MCPへの毎回の照会 |

進行処理はローカル側の薄い接続処理に置く。公開操作を一つに見せるために、MCP発行サービスからWeb保存サービスを呼び出す設計にはしない。MCPのツールとして接続処理を提供する場合も、ローカルMCPとリモートの証明発行MCPを区別する。

ローカルには、構造化入力を受ける公開操作を設ける。内部でリモートMCPの検証ツールとWebのJSON APIを呼び出す。接続先は運用者が配布する環境設定から選び、AIが指定した任意のURLへ送信しない。

共有してよいのは、版付きスキーマ・正規化・署名検証・表示用の純粋な部品である。DB、セッション、状態遷移、秘密鍵、デプロイ条件は共有しない。Web保存にはWeb用ストレージが必要だが、その設定をMCP発行の成立条件にしない。

## 4 送信データと証明の契約

### 4.1 正本となる見積データ

新しい正本を構造化データの `EstimateResult` とする。形式名は `oes/estimate-result/v1` を案とし、少なくとも以下を持つ。

- 契約版、測定日時、TEST等の計算区分。
- 工数のp25・中央値・p75、人日換算基準、参考金額・通貨。
- 機能規模集計、全体／部分の区分、取得充足、暫定・未確認の件数と規定の理由コード。
- 使用ルール・計算係数の参照版、採用した為替値・観測日・取得日・出典識別子。
- 証明の対象範囲と区別して表示する、品質申告情報。

構造化データからMarkdown・PDF・Webを生成する。生成時に係数や為替を再取得しない。元runや生成済みMarkdownの存在は、データ送信・再表示の前提にしない。

### 4.2 匿名化と送信範囲

公開可能な項目をスキーマの許可リストで固定する。案件名・企業名・顧客名・機能名・自由記述・URL・パスを載せられる汎用欄を追加しない。出典は承認済みの出典識別子等に限定し、任意URLを受け取らない。

| 情報 | MCPへの送信 | Webへの保存・公開 |
|---|---|---|
| EstimateResult | 送信 | 保存・公開 |
| 匿名の数値モデル、配布整合性などの検証入力 | 送信。機能識別は生成した無意味なIDとし名称を含めない | 送らない |
| 証明番号・発行日時・署名・検証範囲 | MCPが返す | 保存・公開 |
| 操作ID、再試行用情報、公開停止用の秘密情報 | 必要な担当処理だけで扱う | 公開表示しない |
| ソース、ローカルパス、案件識別情報、根拠、判断台帳 | 送らない | 送らない |

未知項目は黙って受理せず拒否する。除外すべき項目が残った場合はローカルで停止し、送信内容を修正する。集計値でも他の情報と照合される可能性はあるため、「機密になり得ない」と断定せず、公開する実データを利用者が確認できるようにする。

### 4.3 証明の対象

署名対象は、版を固定した方法で正規化したEstimateResultのハッシュと、発行元・証明番号・ルール版・検証範囲等の署名文とする。既存の正規化JSON・Ed25519の実装を再利用する。小数の表現、日時、単位、丸め、欠損とnullの区別まで契約で固定する。

MCPは提出された数値モデルを検証・再計算し、EstimateResultの数値と条件の一致を確認した後に署名する。値が合わなければエラーを返す。確定結果と違う値を黙って採用して公開しない。不整合の修正が必要なら、原因を解消して新しい要求を固定し、当初の承認範囲内であることを再検査する。算定値が未確定だったという理由で、正常な算定後に新たな同意を要求しない。

新しい証明形式を `oes/estimate-proof/v1` とし、Markdown本文に署名する旧 `oes/document-proof/v1` と識別・検証方法を分ける。番号だけでは証明とせず、データ一致・信頼済み公開鍵・署名を検証する。

証明は数値整合・指定ルールとの対応・発行元を示す。ソースの網羅性、AIの意味判断、為替の真正性、実工数・納期・市場価格、提出者本人性を保証しない。Markdown・PDF・HTML全体に電子署名したという表示もしない。

### 4.4 通信の最小契約

実装するAPI名・引数・ルートの詳細はSYSTEM-IMPLEMENTATION-PLAN.mdを正とする。意味と境界は次を基準とする。

| 操作 | 入力 | 成功応答 |
|---|---|---|
| MCP `issue_estimate_proof` | proof_operation_id、EstimateResult、匿名の検証入力 | データハッシュに結び付いた証明 |
| Web `POST /api/results` | publish_operation_id、EstimateResult、証明、公開停止用秘密情報のハッシュ | public_result_id、canonical_url、result_hash、公開状態、published_at、expires_at |
| Web `GET /results/{id}` | 公開結果ID | 保存済みデータから表示するHTML |
| Web 公開停止API | 公開結果ID、公開停止用秘密情報 | 停止状態 |

Web登録は本番では本番の信頼済み証明を必須とし、未知鍵・改変・別データの証明・テスト環境の証明を拒否する。未証明の自動公開への降格は行わない。鍵は運用者の信頼カタログから取得し、入力に含まれる鍵を信頼しない。

匿名で利用できるAPIには入力容量・項目数・処理量・登録頻度の上限を設ける。これらはサーバー側の検査とし、通常の利用者操作を増やさない。署名秘密鍵はMCP発行側だけに置き、Webとローカルには検証用公開鍵を配布する。MCPへの検証入力をログや監視へ保存しない。

証明発行と公開保存は別の要求として確定する。分散トランザクション、事前受付、ポーリングは導入せず、途中成功をローカルに記録して未完の処理だけ再送する。

## 5 同意と再試行を簡単に保つ

正常フローでの製品側の確認は、解析開始前の一回とする。同意を「これから確定する数値そのものへの承認」ではなく、「今回の対象について、明示した項目・条件で解析・送信・公開する処理への承認」として記録する。将来の別案件まで含む無期限の包括承認にはしない。

開始時の承認記録には、対象と取得範囲、選択された操作、送信・公開項目の契約版、実際の送信先と環境、目的、通貨・計算方針、品質の扱い、公開範囲、保存方針、明示操作と日時を保持する。数値や生成ハッシュはこの時点では要求しない。

算定後にローカル処理が実際の要求を固定し、承認記録の範囲内か機械的に検査する。その承認記録と要求ハッシュを関連付けて送信する。この関連付けは新しいユーザー承認ではなく、事前承認の適用記録とする。後続のWeb登録にも同じ条件検査を行う。内容を検査せず、以前の承認を任意の要求へ流用しない。

同意記録はローカルで管理する。同意済みというbooleanをサーバーが本人性の証明として扱わない。匿名APIはスキーマ・署名・入力制限を検査し、利用者の実際のクリックを検証できると説明しない。公式クライアントは明示操作なしに呼び出さない。

当初の承認範囲内なら、算定値の確定、証明番号の発行、公開URLの発行、通常の品質区分の判定、同一要求の通信再試行では追加同意を求めない。対象拡大、公開項目の追加、送信先・環境・目的の変更、計算方針の変更、本人限定から公開への変更、当初選択していない検証や公開への追加など、承認範囲を超える場合だけ差分を確認する。

禁止した機密項目の混入や署名不正は、同意さえ取れば続けられる例外にはしない。送信を止めて不具合を修正する。取得不足が見つかっても、承認済み範囲内での分割取得や宣言済みの部分試算表示だけなら再同意は不要とする。範囲外のソース読取が必要なら、その追加範囲だけ確認する。

承認は未送信処理について取り消せる。取消を検出した後は後続送信を止め、取消前に完了していた処理は正確に報告する。公開済みなら公開停止操作を案内する。取消後は以前の承認で再開しない。同じローカル記録からの再開は同じ作業として扱い、別の見積依頼へ同意を流用しない。

ローカルの再開記録には、固定データ・操作ID・承認の対応・受領した証明・登録応答を保持する。保存先はローカルの状態管理とし、利用者によるファイル選択を要求しない。実行中は構造化データだけで処理できる。再開記録を保持できない環境では、会話を閉じた後の復旧を保証しないことを明示し、未保存の秘密情報や操作IDを保持済みと扱わない。

MCPとWebのそれぞれで、同一操作ID・同一要求は同じ成功結果を返し、同一ID・異なる要求は競合として拒否する。並行送信でも一件だけ確定する。Webの登録確定後に応答が失われても同じURLを返す。取得したURL・本文・秘密情報をエラーログへ無差別に出力しない。

| 発生状況 | 利用者への表示と復旧 |
|---|---|
| ローカル見積のみを選択 | ローカル見積・PDFを保持して終了。検証送信もWeb登録もしない |
| 検証のみを選択 | 検証・証明まで完了して終了。Web登録はしない |
| 検証が不一致 | 公開せず原因を解消する。修正要求が当初の承認範囲内なら再同意は不要 |
| 承認範囲を超える操作が必要 | その操作だけ停止し、理由と変更差分を一度確認する |
| MCPの通信失敗 | 同じ検証依頼を再送。再解析しない |
| 証明取得後にWeb登録が失敗 | 証明を保持し、Web登録だけ再送する |
| 登録応答が消失 | 同じ公開操作を再送して同じURLを取得する |
| PDFの生成・取得失敗 | Web公開と区別し、同じ固定データからPDFだけ再生成する |
| 公開停止済みの操作を再送 | 停止状態を返す。自動復活しない |
| 公開期限切れの操作を再送 | 期限切れ状態を返す。期限延長・自動再公開はしない |

自動再試行は回数を制限し、失敗時に「Web公開を再試行する」を提示する。新しい受付を作り直し続ける処理や、バックグラウンドでの無期限再送は設けない。

## 6 Web保存と公開停止

### 6.1 保存する結果

Webには公開可能なEstimateResultと証明、ランダムな公開結果ID、公開日時・公開終了日時、公開状態、再送照合情報、公開停止用秘密情報のハッシュを保存する。匿名の詳細数値モデル・ローカル承認文・ソースは保存しない。MCPの発行記録も、操作ID・要求指紋・証明など再送に必要な最小情報に限定する。

保存と公開を一度の登録で確定し、成功は永続化後に返す。保存後の見積データは不変とし、再見積は新しいデータ・証明・公開操作にする。通常の描画変更で数値・係数・為替を上書きしない。

### 6.2 閲覧範囲と期間

結果はログイン不要で閲覧できる。公開URLを知る人は共有でき、「本人限定」「秘密のページ」と表示しない。初期仕様では一覧検索・サイトマップ掲載を提供せず、検索エンジンへの掲載も抑制する。ただし検索除外はアクセス制御ではない。

Web公開は最初の公開保存完了日時から1年間（365日）とする。サーバーが `expires_at = published_at + 365日` をUTCで一度だけ確定し、画面には利用者に分かる公開終了日を示す。同一操作の再送やページ閲覧で期限を延ばさない。公開期間はWeb側の管理情報とし、見積データの数値やMCPの証明契約へ混ぜない。

公開終了日時以降は、本文やWeb経由のPDF・データ取得を止め、「公開期間が終了しました。ダウンロード済みのPDFをご利用ください」と表示する。期限は読取時にも検査し、定期削除の遅延によって閲覧可能期間が延びないようにする。期限切れ本文は定期削除し、再送による復活を防ぐ最小記録を保持する。

自動延長、延長通知への回答待ち、通常画面の延長ボタンは設けない。公開終了後に利用者が再公開を明示的に希望した場合は、対象結果と新しい1年間の公開を確認して別の公開操作とする。開始時の承認で期限切れ結果を自動再公開しない。

利用者がダウンロード済みのPDF・Markdown・JSON・証明データは、この公開期限によって消えたり閲覧不能になったりしない。PDFの主要内容はWeb接続なしで読めるようにする。PDF内に公開URLを載せる場合は公開終了日も付記し、リンクの期限とファイル自体の利用可能性を区別する。

運用上の保管上限に達した場合は新規登録を制限し、既存の結果を無告知で30日失効へ戻さない。

### 6.3 最低限の公開停止

誤公開や取消に備えて、公開停止だけは残す。利用者アカウントを増やさず、ローカル側で公開操作ごとに生成した十分に強いランダムな秘密情報を管理権限にする。Webにはハッシュだけを登録する。生の秘密情報は公開URL・ページ・証明・共有PDF・ログに含めない。推測可能な操作IDやデータハッシュを管理権限に代用しない。

停止は所有者側の管理操作から行い、閲覧ページに誰でも実行できる削除ボタンを置かない。秘密情報はホストの非公開状態に保持し、必要なら利用者が管理用バックアップを取得できるようにする。紛失時に公開URLだけで管理権限を復元しない。運営者による停止は別の認証済み運用手段を使う。

停止後は本文を配信せず、結果ページに停止状態だけを示す。初期仕様は本文をCDNへキャッシュせず、停止後に古い本文を配信しない。重複再送で復活させないため、公開ID・再送照合情報・停止状態の最小記録は残す。運営が本文削除を行う場合も同じ扱いにする。閲覧者が取得済みのコピーまで回収できるとは説明しない。

公開停止および1年間の公開期限終了は、証明の暗号学的な失効とは異なる。Web公開期限が来たことだけを理由に署名を無効としない。表示時にオンライン失効を調べない場合は「証明の失効状態は未確認」とし、表示のたびにMCPへ接続しない。

## 7 Webとチャットの画面

結果ページは「総工数 → 品質・参考幅 → 金額・規模 → 証明 → 詳細」の順とする。主要ソース不足は見出しから分かるようにする。技術的な生JSONを通常の詳細表示に代用せず、人が読める項目名で説明する。

| 画面要素 | 方針 |
|---|---|
| 総工数の中央値 | 最上部で大きく表示 |
| 全体／部分、TEST、暫定・未確認 | 総工数の近くに表示 |
| 公開URL・共有 | コピー操作を提供 |
| 公開終了日 | 結果URLの近くに表示。公開から1年間と説明 |
| PDF | チャットで標準出力。Webでも同じ保存データから取得可能にする |
| 証明 | 検証状態と保証範囲を短く表示し、詳細を展開可能にする |
| この結果を後日見返す | 削除。現在のURLをそのまま利用する |
| 一時表示、30日保存、延長 | 削除 |
| 本人限定・未公開の表示 | 新公開結果から削除 |
| 確認コード、転送受付、ファイル選択 | 標準フローから削除 |

WebのPDFは保存済みデータと証明だけを入力とし、MCP再計算や元runを要求しない。生成障害でも結果ページは閲覧できる。画像・HTML等の任意コンテンツを公開データに受け入れず、固定テンプレートで安全に描画する。

## 8 削除と互換の範囲

| 現行要素 | 新規フローでの扱い |
|---|---|
| Markdown本文必須の検証依頼・署名 | 構造化結果の新契約へ移行。旧検証方式は別に保持 |
| `src/local/web-handoff.ts`のファイル選択式受渡し | JSON登録とURL返却へ置換 |
| `src/local/document-consent*` | 開始時の項目別事前承認と、算定後の要求への適用記録を分離。0.11.1の要求別再送記録を参考にする |
| `src/local/create-document.ts`・`document-result.ts` | 構造化データの生成・表示と、ファイル書出しを分離 |
| `src/issuer/*`・`src/proof/*` | 数値検証・署名・再送を再利用し、新証明契約に対応 |
| `src/web/document-preview.ts`・`document-worker.ts` | 新規導線は保存済み結果のGET表示へ。保存なしPOSTは旧互換に限定 |
| `owner-preview`・`preview-transfer`・承認コード・進捗ポーリング | 新規フローから呼ばない。利用実態を確認して整理 |
| `saved-estimates`・Auth0・ブラウザーセッション | 旧本人限定結果の互換用。新公開登録・閲覧の条件にしない |
| 期限掃除・延長ジョブ | 旧15分・30日の処理は旧レコードに限定。新結果は365日の閲覧期限検査と期限切れ本文の削除に対応し、延長ジョブは追加しない |
| Skill・ツール宣言・カード・配布・CI | 開始時一回の同意と承認範囲内の継続を明記。工程ごとの再同意を要求する旧手順を除去 |

既存の本人限定結果は自動公開しない。新しい公開ページへ移す場合は、公開対象を再表示して明示承認を取る。既存URL・鍵・証明の検証能力を保持し、旧Markdownの証明を新データの証明として流用しない。

SYSTEM-SPEC.mdとSYSTEM-IMPLEMENTATION-PLAN.mdは改訂済み。実装時にDOCUMENT-OPERATIONS.mdの通常手順を置き換える。既存受入記録は当時の証拠として保持し、新フローの受入を別節で追記する。互換コードは新フローからの参照がないことを確かめ、利用実態と保持対象を確認してから削除する。

## 9 実装と受入の順序

最初に、合成の構造化見積データで、実ホストの開始時一括同意から「算定結果の確定 → MCP証明 → Web保存 → HTTPS URLを開く」までを細く通す。算定前の承認が算定後の送信へ適用でき、ファイル選択・ローカルHTML・各工程での追加承認が不要であることを確認する。これは最終受入に代わるものではなく、境界の成立確認とする。

続いて契約と再試行を固定し、実際の算定結果・カード・PDFへ接続する。標準フローが通った後に旧導線と不要コードを整理する。実装依頼時は途中段階で停止せず、次の受入条件まで進める。

| ID | 受入条件 |
|---|---|
| A01 | 開始画面に対象範囲と全工程を示し、読取・検証・公開を一度の操作で項目別に承認できる |
| A02 | 開始承認前はソース本文解析も見積由来の外部登録も0件。検証・公開未選択時も該当送信は0件 |
| A03 | 実ホストで開始時に全工程を選択すると、算定値の確定後も製品側の追加同意0回でURL取得まで進む。ホスト側の確認は別に記録する |
| A04 | Markdown/PDFを保存していない構造化入力でも、証明取得とWeb登録が成立する |
| A05 | 新規公開の登録・閲覧がOAuthなしで動き、通常のGETリンクで新しいブラウザーからも開ける |
| A06 | 15分・30日・公開終了直前は閲覧でき、公開から365日の境界以降は本文・WebのPDF・データを取得できない。削除ジョブ未実行でも期限を守る |
| A07 | 同一要求の再送・並行送信・応答消失で、証明・公開結果・URLが重複しない |
| A08 | 証明取得後にWebが停止しても再解析・再同意せず登録だけ再開する。当初の承認範囲を超える変更だけ追加確認する |
| A09 | 改変・未知鍵・テスト証明・別結果の証明・機密を含む未知フィールドを拒否する |
| A10 | 全体／部分・主要数値・計算条件がチャット・PDF・Webで一致する |
| A11 | MCP停止中も保存済み結果を表示できる。Web停止中もローカル結果・PDFとMCPの単独検証を利用できる |
| A12 | 公開停止には正しい管理権限が必要で、停止後は再送でも復活せず、管理秘密が公開物へ漏れない |
| A13 | 旧本人限定URL・旧証明を壊さず、本人限定結果を無承認で公開しない |
| A14 | 実ChatGPTで開始時の一括同意から解析・カード・PDF・証明・保存・URLの実表示まで通す |
| A15 | 算定値・証明番号・公開URL・宣言済み品質区分の確定では追加同意せず、要求が開始時の許可項目・対象・送信先と一致することを検査する |
| A16 | 対象外ソース・未承認の送信先・公開項目の追加を遮断し、必要な差分だけ確認する。禁止情報の混入は同意で迂回しない |
| A17 | 初期未選択、検証と公開の依存、三つの選択パターン、取消後の送信停止、別案件への同意流用禁止が動く |
| A18 | 閲覧・再送で公開期限が延びず、期限切れ操作の再送で復活しない。保存済みPDFは公開期限後もオフラインで読め、公開期限だけで証明を無効扱いしない |

署名、登録、描画、ローカル進行処理はそれぞれ固定入力で単体試験できるようにする。Web保存・表示の試験には信頼鍵と署名済みfixtureを使い、実MCPを必須にしない。MCP試験にはWeb DBを与えない。再送と並行登録は実際に使うストレージでも検査する。

受入記録はローカル・ステージング・本番・実ホストを分け、版・日時・入力区分・実表示の証拠を残す。単体試験件数やAPI成功だけで、利用者が全工程を通せたと判断しない。

## 10 本案で採用する前提と対象外

本案の推奨前提は、公開URLはログイン不要、検索一覧には掲載しない、公開期間は1年間（365日）、新規公開は数値検証の証明を必須、管理は公開停止用秘密情報による方式とする。これらは本案全体の検討対象であり、未回答事項を通常フローの停止条件として追加しない。

本人限定クラウド保管、アカウント別履歴、共同編集、公開結果の検索市場、課金、任意の説明文の掲載は今回の対象外とする。必要になった時点で別機能として追加し、見積からURL取得までの基本フローへ持ち込まない。

保存を標準にすることで、利用者の操作を減らす。一方で、証明発行とWeb保存は独立した契約として保ち、各サービスの障害・設定・更新が不要に波及しない構成を維持する。
