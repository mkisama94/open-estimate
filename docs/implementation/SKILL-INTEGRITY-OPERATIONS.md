# スキル整合性の申告確認・リリース運用

**0.7.0追記**：スキル整合性検査を維持し、正規ルールの配信・固定・評価時の版確認を追加しました。初回通常リリースにルール履歴を同梱し、スキルとルールの移行期限を別々に保持します。本文だけの更新は `npm run rules:release`、詳細は[中央ルール運用](CENTRAL-MEASUREMENT-RULES-OPERATIONS.md)を参照してください。未確認の配信がある間は別候補への切替を止め、同じ候補で再開します。


数値モデルと、利用する配布スキルのID・版・整合性確認用ハッシュを送信します。対象ソースコード、名称、説明、ファイルパス、根拠本文、対象ソースのハッシュは送信しません。正規値の意図的な偽装申告を防ぐ認証・実行証明ではありません。

## ローカル検証と公開

通常のビルド・テスト・plugin:packは外部へ反映しません。plugin:packの出力は `release/local-marketplace`、状態はLOCAL_VALIDATION_ONLYです。正規配布先は `release/desktop-marketplace` のままです。

- `npm run release -- --version <次の版>`：prepare、publishを順に実施します。公開には既存Wrangler認証環境が必要です。
- `npm run release:prepare -- --version <次の版>`：版更新、build、全テスト、pack、両コピー照合、smoke、履歴から候補レジストリ生成、Workerのdry-runを行います。候補は `release/staging/<版>/` です。
- `npm run release:publish -- --version <準備済み版>`：候補ファイルを再検査し、固定Workerをデプロイします。実MCPのポリシーhash、USD合成モデル成功・不一致拒否を確認して履歴を保存し、同じ配布物を昇格します。ソースから再ビルドしません。
- `npm run deploy:mcp -- --version <準備済み版>`：同じ検査・公開経路を通ります。`deploy:mcp:check` は固定候補の検査とdry-runだけです。

package.jsonが版の管理元です。manifestとplugin.jsonはbuild時に同期します。公開済み履歴は `profiles/skill-releases.json` に原子的に保存します。通常の版管理・バックアップに含めてください。未登録ハッシュはクライアント申告から登録しません。同版の異なるハッシュは拒否します。受付済み版は通常更新で削除せず、revokedは再生成で復活しません。

## 初回移行と再開

初回publishがenforcement_atを14日＋処理余裕1時間後に自動設定し、固定Workerのランタイム設定として渡します。配布昇格直前にも14日以上残ることを検査します。未公開のまま中断して期限不足になった場合は再実行時に日時を確定し直して同じWorkerを再デプロイします。配布可能になった初回公開日から最低14日を確保し、公開済み履歴の期限は以後延長しません。

移行期間中は申告なしだけLEGACY_UNCHECKEDで再計算し、申告がある不一致は拒否します。期限以降は申告なしを拒否します。未初期化レジストリも申告なしを許可しません。直接Wrangler操作を通常の公開手順に使わないでください。

中断時は同じpublishを再実行します。`publication.json` が到達段階を記録し、再実行時も本番ポリシーを確認します。履歴保存後の昇格失敗も同じ候補から再開できます。`operation.lock` が残った場合は、リリース処理が実行中でないことを確認してこのロックだけを除去します。配布・Worker・レジストリのいずれかが変わった候補は公開しません。

Workerコードを前版へ戻す場合は、現在の公開済み履歴・停止情報を保持したコードで新しい候補をprepareし、publishします。古いWorker成果物をそのまま戻さないでください。外部ストアへの提出は自動化の対象外です。ローカル配布可能と外部提出済みを区別します。

## 検証の境界

実ファイルのバイト列を検査します。Git設定などで改行が変わった開発コピーは同じ版の正規配布物と一致するとは限りません。受理値は最終packの両コピーから生成します。manifestの書換えだけではサーバーの登録値は変わりません。検査対象はスキル配下であり、全ランタイムの完全性や意味判断は証明しません。

Work／Codexの新しいチャットでポリシー取得→実計算→scan→prepare→export→送信→表示を確認する実機受入は、ローカル自動試験とは別です。本番反映・外部提出・実機評価は実施証拠がある場合だけ完了と記録します。
