# ローカル利用体験と外部送信の確認

更新日：2026-10-31（JST）。状態：採用済みの目標仕様、実装・配布・実ホスト受入は未実施。基準コードは0.14.0。本書は[SYSTEM-SPEC.md](SYSTEM-SPEC.md)の詳細仕様であり、旧文書の読取同意・開始カード必須・再計算時のローカル再承認を置き換える。

## 1 商品価値と設計原則

Open Estimateの価値は、対象ソースをOpen Estimateのクラウドへアップロードせず、利用者が許可したプロジェクトをローカルで走査して工数を算定できることにある。外部送信の説明と確認は、何が送られず、何だけが送られるかを利用者が理解し、安心して選べるようにするために設ける。ローカル作業に認証に似た儀式や重複同意を課すことを目的にしない。

厳密さは機械的な境界検査、計算の再現性、署名・証明、公開の認可、固定結果の整合性で確保する。利用者のクリック数を厳密さの指標にしない。

「ローカルスキャン」は完全オフラインや、ソースがどのクラウドでも処理されないことを意味しない。ホストのAIがソースを読む場合は、そのモデル提供元で処理される場合がある。商品説明・開始案内・送信画面でこの境界を統一し、確認できない環境を「ソースのクラウド送信ゼロ」「完全ローカルAI」と表示しない。

## 2 ローカル作業を開始する条件

利用者による見積・再計算・再開の依頼と、ホストの既存権限で許可された対象が明確なら、その依頼を作業の根拠として走査・本文読取・解析・算定・ローカル保存・結果/PDF表示を開始する。プラグイン独自の読取チェック、開始ボタン、同じ内容のチャット回答を追加の必須条件にしない。

依頼がなくプロジェクトを開いただけでは見積を開始しない。ホストの読取権限だけを別プロジェクトの見積依頼とみなさない。対象が不明な場合や、依頼の範囲を超える追加対象が必要な場合は、その不足だけを質問する。範囲内のファイル一覧、取得計画、容量、除外は自動で作成・記録し、短く案内する。案内への返答待ちは設けない。

パストラバーサル、symlink経由の逸脱、秘密情報・依存物等の保護除外、取得上限、対象コードを実行しない制約は維持する。ホストが要求する実際のアクセス許可や操作承認は尊重し、製品側の同意と混同しない。不要な権限昇格や保護領域への保存を標準経路の前提にしない。

## 3 確認の判断表

| 操作・状況 | 製品側の扱い |
|---|---|
| 許可された対象の見積依頼 | 読取の再確認なしで開始。対象と処理の短い案内のみ |
| 対象・開始方法が依頼から明確 | 同じ選択をカードでやり直させない |
| 対象や引継ぎ元が複数あり判断不能 | 必要な選択だけ質問。読取・送信確認を重ねない |
| 範囲内の分割、再取得、キャッシュ修復、下書き修正、PDF再生成 | 自動処理。新旧記録と整合性を保持 |
| 取得不足・未読・未確定判断がある | 品質を表示。安全に算定できる取得済み部分の参考値に追加許可は不要。全体工数に昇格させない |
| 当初依頼に含まれるファイルが計画から漏れていた | 保護除外に触れなければ計画を修正して取得。変更履歴を残し、単なる計画変更で再同意しない |
| 別プロジェクト、明示除外の解除等、依頼を超える対象追加 | その差分だけ確認。機械的な保護除外は同意で解除しない |
| 公開ルール・為替等の取得 | 対象由来情報を載せない通信として案内。通常の機能利用として扱い、読取同意の代わりとなる必須確認を増やさない。ホスト権限は必要 |
| 見積由来データの検証送信・Web公開 | 送信範囲を説明し、該当操作の明示意思を確認してから実行 |
| 同じ外部要求の再試行・同じ作業の再開 | 有効な既存承認を照合して再利用。再同意・新しい公開期限を作らない |
| 新たな見積結果の外部送信・再公開 | 旧見積の承認を自動流用しない。今回の依頼が説明済み条件での送信・公開まで明示していれば、その依頼を記録し、同じ質問を繰り返さない |
| 送信先・項目・目的・公開範囲など、承認条件の変更 | 影響する外部操作のみ止め、差分を確認。独立したローカル作業は継続 |
| 禁止情報の混入、署名不正、固定結果との不一致 | 拒否して原因を修正。同意で迂回しない |

取得不足を検知するゲートは維持する。部分試算が可能なときは専用の取得・評価経路を使い、`analysis_ready`、取得充足、未読記録を無条件に書き換えない。部分値すら妥当に出せなければ未算出と原因を示す。

## 4 通信を三つに分けて説明する

| 通信 | 許容する内容 | 確認と表示 |
|---|---|---|
| ホストAIによる解析 | 利用中のホストが、依頼と権限の範囲でソースをモデル入力として扱う場合がある | ホストのデータ取扱いに従う。プラグインによるソースアップロードと区別して説明 |
| ルール・為替等の取得 | プロトコル、配布スキルID/版/整合性、ルール参照、通貨等の必要な制御情報。対象ソース・パス・対象hash・見積数値・判断台帳は含めない | 通常の取得として説明。見積由来データ送信の承認に読み替えない |
| 任意の検証・証明、Web公開 | MCPには匿名数値モデル、配布整合性、ルール・計算条件、構造化結果。Webには集計結果、計算/為替条件、品質集計・規定コード、証明 | 実際の送信先・項目・目的・保存/公開条件を説明し、対象と操作に結び付く承認を保持 |

Open EstimateのMCP/Webへは、ソース本文・抜粋・アーカイブ、対象パス、対象ソースhash、企業名・案件名・機能名、根拠・判断台帳・自由記述を送らない。検証・公開を選ばない場合、見積由来の数値モデル・結果・hashも送らない。送信しない場合に「通信なし」とは表示しない。

既存の正規ルール取得・整合性検査を緩和しない。必要な公式ルールが得られない場合は未実行と理由を示し、古いルールへの無断切替や完全オフライン動作を約束しない。Web公開や証明発行の停止だけをローカル算定の開始条件にしない。

## 5 利用者に見せる導線

標準は「見積依頼 → 対象とデータ取扱いの案内 → 走査・解析・算定 → 結果とPDF」。検証・公開は任意の追加工程とし、その選択待ちでローカル解析を止めない。希望がなければ質問を繰り返さずローカル結果で完了する。

開始案内の例：

> 指定されたプロジェクトを読み取り、工数とPDFを作成します。ソースコードはOpen Estimateのサーバーへ送りません。AIによる解析では、利用中のAIサービスのモデル提供元で処理される場合があります。検証・証明やWeb公開を希望する場合は、送信する数値情報と公開範囲を確認できます。

外部操作を希望したときは、検証・証明と365日のWeb公開を区別し、一画面または一度のチャット回答で確認する。未承認の操作は初期未選択。公開には検証が必要なことを同じ説明内に含める。読取チェックや「ローカルのみ」の必須選択を置かない。検証だけ、または検証と公開をまとめて選べる。

送信確認には、実際の接続先、MCPだけに送る項目、Webで公開する項目、送らない情報、URLを知る人がログインなしで閲覧できること、最初の公開から365日で終了することを示す。短い要約から詳細を参照可能にし、詳細の展開・スクロール・再入力を承認条件にしない。

見積前に検証・公開まで希望された場合も、同じ説明済み条件への実回答を承認として記録できる。説明が不足していればその外部操作だけを確認する。算定値は後から確定すると説明し、結果確定・証明番号・URL・品質区分の発生だけで再確認しない。後から追加された外部操作のために解析をやり直さない。

無回答・時間経過・カード表示・見積依頼だけを外部送信の承認としない。ローカル作業を進める根拠と、外部送信を進める根拠は別に扱う。

外部操作だけの取消は未送信の該当工程を停止し、ローカル結果は保持する。見積全体の中止を求められた場合はローカル作業も停止する。既に送信済みの処理や応答不明の処理は「送信なし」とせず、同じ操作IDで状態を照会して報告する。

## 6 内部記録・開始方法・互換

ローカルの作業記録と外部送信の承認記録を分離する。前者には依頼の根拠、対象、範囲、計画、開始方法、snapshot/draft/runへの対応を記録する。ユーザーの新たなクリックを作り出したり、内部の記録作成を利用者の本人認証と呼んだりしない。

後者には承認された対象/結果・操作、説明した条件と契約版、送信先・環境・項目・目的・計算方針、公開範囲と期間、実際の回答/操作、日時、取消状態を保存する。外部送信直前に固定要求との対応を検査し、要求hashと操作IDを関連付ける。ローカル記録の存在を外部承認の代わりにしない。

NEW/RECALCULATE/RESUMEの意味は[START-METHODS.md](START-METHODS.md)に従う。明確な依頼から決定し、判断できない場合だけ選択を求める。再計算でローカル読取の同意を取り直さない。再開でworkflow・承認・固定結果・操作IDを捨てない。新結果の作成と、旧結果の変更・公開停止を分ける。

現行0.14.0の`selection.read`・`explicit_answer`必須契約を単に常時true/定型回答で通過させる実装は禁止する。ローカル開始と外部承認を分離した版付き契約へ移行し、CLI/MCP/Skill/カード/配布物を合わせて更新する。旧データの実際の読取同意は履歴として保持できるが、新規ローカル作業の要件にしない。旧外部承認は記録された同じ要求・条件で有効か検査し、新しい公開へ自動変換しない。整合性のとれた状態移行と互換検査を行い、既存記録のフラグの一括書換えは行わない。

署名、信頼鍵、発行元・環境の検査、数値一致、固定結果、二重発行防止、期限、公開停止秘密、機密の許可リスト、公式ルール・配布整合性の検査は変更しない。認証・証明上の保証範囲を広げない。

## 7 受入条件（LUX）

以下は今回追加する未実施の受入条件。過去のA01〜A18や0.14.0の合格を転記しない。

| ID | 条件 |
|---|---|
| LUX01 | 必要なルール等が利用可能な正常系で、許可済み対象への見積依頼から製品側の追加質問・読取チェック0回で本文解析と結果/PDFへ到達する |
| LUX02 | 依頼なしでは開始しない。対象不明・依頼外の追加だけを質問し、範囲逸脱・保護除外は拒否する |
| LUX03 | 外部操作の無選択・無回答時に見積由来データの送信0件。外部取消後の新規送信0件で、ローカル結果は保持する。送信済み/応答不明は照会し、見積全体の中止ではローカル作業も停止する |
| LUX04 | ルール/為替の通信に対象由来情報が含まれず、ホストAIとの境界も正確に表示する |
| LUX05 | 検証だけ/検証と公開を一度で選択でき、送信先・項目・365日・閲覧範囲が分かる。読取の再確認はない |
| LUX06 | 説明済み条件での明示依頼を再質問せず利用する。曖昧な「見積もって」やカード表示だけでは外部承認にならない |
| LUX07 | 分割・再取得・部分試算・下書き修正・PDF再生成に追加同意なし。欠落・未読・不整合を全体充足へ偽装しない |
| LUX08 | 明示された新規/再計算/再開で開始方法を再選択させない。曖昧な引継ぎ元だけ質問する |
| LUX09 | 新しい再計算結果に旧外部承認を流用しない。同じ再開/再試行は元の有効承認・要求・操作IDを保持する |
| LUX10 | 外部条件変更時は差分だけ確認し、無関係なローカル工程を止めない。禁止情報・不正署名は承認でも通さない |
| LUX11 | 旧workflow/結果/証明/URLを保持し、新旧状態の互換を検査する。架空のexplicit_answerや旧同意書換えを作らない |
| LUX12 | 実ホストでローカルのみ/検証まで/公開まで/再開を確認し、製品の質問数とホストの操作承認数・理由を別々に記録する |

数値・暗号・公開期限等の既存回帰と、外部送信を観測する境界テストを維持する。実装、配布、実ホスト受入をそれぞれ完了報告する。
