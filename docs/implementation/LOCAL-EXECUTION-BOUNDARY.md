## 1. 変更する方針

公開配布するプラグインにローカルstdio MCPを必須としない。ローカルMCPは接続方式であり、利用者側の改変を防ぐ仕組みでも、評価の真正性をサーバーに証明する仕組みでもない。

測定対象は引き続き利用者が許可したローカルプロジェクトとし、Open Estimateサーバーへのソース本文・抜粋・アーカイブの送信を要求しない。対象環境はローカル実行が可能なWorkとCodex。Chatでの利用は補助的なデバッグ用途とし、提供される権限・ツールを確認して扱う。標準ツールや実行環境がないモードで動くと約束しない。

本書は旧仕様の「ローカルstdio MCP必須」「ローカル記録をサーバーで独立検証済みとして扱う」前提に優先する。認証、保存、発行、公開についての未決事項は確定した扱いにしない。

## 2. 移行構成

| 担当 | 役割 |
| --- | --- |
| Skillとホスト標準ツール | 現在の対象の特定、構成の走査、読み取り範囲の確認、AIによる機能・データ移動の分析、結果説明。ホストの権限と実行制限に従う。 |
| 同梱するローカル補助スクリプト | スナップショット、SHA-256、行番号付き読み取り、読み取り範囲記録、根拠参照の整合検査など、反復可能な機械処理。ホストの実行ツールから必要時に起動して終了し、MCPサーバーや待受ポートを設けない。 |
| リモートMCP | 受領した構造化入力の検査、サーバー管理の計数規則・プロファイルによる再計算、表示要求時のFRB公表為替による換算。将来の認証・保存・証明書発行・公開は、それぞれの契約確定後に追加する。 |

接続先ドメインは利用者指定の `https://open-estimate.ai-orchestration.jp/`。MCP接続パスは `/mcp` を設計案とし、デプロイ済みと扱わない。

既存のCollector、CoverageTracker、検証・計数ライブラリを再利用する。単純な情報取得は標準ツールを優先し、ハッシュ・コピー・読み取り台帳などAIに都度コードを生成させると不整合が生じる処理を補助スクリプトにまとめる。実行言語、依存関係、OS別の起動方法はクリーン環境検証を踏まえて具体化し、作成者PCの絶対パスを配布物に埋め込まない。

## 3. セキュリティ上の役割を分ける

### 利用者の端末と情報を保護する制御

ローカルMCPを外しても、次の制御は維持する。

- ファイル構成を先に示し、対象の確認後に本文を読む。対象が変わったら確認し直す。
- 許可範囲外のパス、シンボリックリンク、秘密ファイル、不要な生成物を適切に制限する。
- ソースの量と応答の量を制限する。未読・上限超過を完全評価として扱わない。
- 対象プロジェクトのコード・ビルド・テスト・依存インストールを実行しない。補助スクリプト自体の実行とは区別する。
- 測定対象内の命令文を、測定規則・送信先・権限を変更する指示として採用しない。
- キャッシュの保存先・保持期間・削除方法を明示する。秘密情報のファイル名による除外を完全な内容検出と説明しない。

これらは通常利用での誤操作・過剰読取・漏えいを減らす制御である。ホストやOSの権限制御に従い、利用者が自分の端末のプログラムを書き換える行為への改変耐性とは区別する。

### サーバーが信頼できる範囲

| 情報 | サーバー側の扱い |
| --- | --- |
| 機能分割、E/X/R/W、根拠、読取履歴、対象同意、ソースハッシュ、ローカル版番号 | クライアント申告。ローカルMCPでも補助スクリプトでも同じ。単独では独立した真正性の証明にならない。 |
| スナップショットとハッシュの一致 | ローカルの再現・変更検知には有用。利用者はソースと記録を一緒に変更できるため、正しい原本であることの証明には使わない。 |
| 入力Schema・参照整合性・計数の算術・サーバーの基準での再計算 | サーバー自身で実施した検証として記録できる。入力の意味が正しいこととは別。 |
| 保存・閲覧・更新の権限 | サーバーの認証・認可で強制する。クライアントの所有者ID・同意フラグだけで権限を与えない。 |
| 将来の署名 | 受領した評価と計算結果、採用基準・版など署名対象の内容を固定したことを示す。ソース実在性・網羅性・AIの意味解釈を証明しない。 |

不正なクライアントはローカル検査を省いて直接リモートAPIを呼べる前提とする。サーバーは型・件数・長さ・参照・値域などを独立検証し、算出済みCFP・工数・金額・ローカル署名を無条件に採用しない。署名鍵や認証上の秘密を配布物へ埋め込まない。

サーバーがソースを受領しない限り、整合した虚偽の機能モデルを完全に見抜くことはできない。ソース非送信と独立したソース監査を同時に達成したと説明しない。

## 4. 送信境界

ソースと詳細な根拠はローカルに残す。サーバーへ送る構造化データの許可リストは別途確定する。現行Assessment全体をそのまま送ることは承認済みと扱わない。機能名・説明・パスにも機密が入り得るため、自由記述を単にJSON化しても安全な送信形式にはならない。

AIの解析に必要な本文がモデル提供元へ渡る経路と、Open EstimateのリモートMCPへの送信は分けて説明する。ソース非送信は正規実装のデータ経路について検証する要件であり、改変クライアントが任意の内容を送信できないという保証ではない。

## 5. 公開配布との関係

2026-10-18確認の公式資料では、Skillに実行可能なスクリプトを同梱でき、決定的な計算やファイル処理に使用できる。MCPのないデスクトップ実行プラグイン向けの申請手順も記載されている。一方、ローカルMCP申請は承認済みパートナーに限定される。

- [Build skills](https://developers.openai.com/plugins/build/skills)
- [Submit desktop-only plugins](https://developers.openai.com/plugins/deploy/desktop-only)

この構成変更を審査条件の迂回や審査通過保証として説明しない。ローカル実行が必要であることを正しく申告し、スクリプト・依存関係・リモートMCPを含む最終パッケージの申請条件と動作を確認する。リモートMCPとの混在時の申請設定・アクセス可否も別途確認する。
