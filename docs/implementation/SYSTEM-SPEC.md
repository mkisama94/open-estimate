# Open Estimate システム仕様

更新日：2026-10-28。状態：実装対象の目標仕様。現行0.11.1からの改修内容を定める。実装・配備・実ホスト受入の完了を意味しない。

## 1 目的と優先順位

利用者は解析開始前の一画面で必要な処理に同意し、見積結果・PDF・希望した場合の証明付きWeb結果URLを得る。標準フローで同じ同意を取り直さない。Web結果は公開完了から1年間（365日）閲覧可能とし、ダウンロード済みPDFはその後も利用できる。

本書と[SYSTEM-IMPLEMENTATION-PLAN.md](SYSTEM-IMPLEMENTATION-PLAN.md)を実装の正本とする。[改善仕様案](WEB-PUBLICATION-SIMPLIFICATION-PROPOSAL.md)は設計背景と画面文言の参照元とする。旧方式の運用・受入記録は当時の証拠として保持し、旧手順を新規フローへ持ち込まない。

## 2 責務とデータ

| 処理系 | 担当 | 依存させないもの |
|---|---|---|
| ChatGPTローカル | 範囲確認、一括同意、取得・解析・算定、結果・PDF、検証と公開の進行、再開 | Web内部状態・DB、発行秘密鍵 |
| リモートMCP | 版付きルール、数値検証、構造化結果への証明、最小発行記録 | Web保存、URL、ブラウザー、利用者ログイン |
| Web | 証明検査、結果保存、URL発行、表示、期限、公開停止 | 再解析・再計算、元run、MCPへの毎回の照会、OAuth |

共有契約は構造化したEstimateResultと証明である。Markdown・PDFは同じ確定結果から生成する出力形式とし、ファイルの保存・読取・選択を外部送信の必須条件にしない。Web保存はWeb用ストレージを使い、MCP発行記録とは分離する。

## 3 標準フローと同意

本文を読まない構成確認 → 対象範囲・全工程の提示 → 開始時の一括同意 → 取得・解析・算定 → 結果・PDFの表示 → 選択した場合のみ検証・証明 → 選択した場合のみWeb保存・URL提示。

開始画面では、読取・解析、匿名の数値モデル等の検証送信、集計結果・証明の1年間の公開を別の未選択チェック項目にする。利用者は選択を確定して一度だけ開始する。読取は必須、検証と公開は任意、公開には検証が必要である。非対応ホストは三つの組合せを一度の選択・回答で確認する。

開始時に、対象・取得範囲・除外・上限、送信項目と送信先、公開範囲、365日の公開期間、品質区分の扱いを示す。ソースはOpen Estimateへ送らず、AI解析ではモデル提供元（OpenAI、Anthropicなど、利用中のAIサービスのモデル提供元のこと）で処理される場合があることを説明する。

同意は今回の対象に対する明示した処理と条件に結び付ける。数値が算定後に確定することを開始時に説明し、算定後に要求が承認範囲内か検査して関連付ける。確定した数値・証明番号・URL・宣言済み品質区分の発生は、追加同意の理由にしない。

対象外の読取、送信先・項目・目的・計算方針・公開範囲の変更、未選択操作の追加だけを差分確認する。機密混入・署名不正は同意で迂回せず拒否する。未送信処理は取消可能とし、既に完了した処理は正確に報告する。ホスト独自の操作確認は回避せず、製品側の確認と分けて記録する。

## 4 取得と算定

計測対象・補助資料・除外・容量見積を実際の取得に反映する。主要ソースを生成物で圧迫させず、範囲内の分割取得に対応する。名前だけで実装を除外せず、取得不足・二重計上・範囲変更を管理する。

固定したルール・係数で算定する。取得不足の部分試算は「全体工数：未算出」を主表示とし、部分の値を総工数としない。開始時に説明済みの部分試算は追加同意を要求せず、範囲拡張時だけ確認する。Web停止をローカル算定の開始条件にしない。

## 5 検証と証明

MCPは匿名の数値モデル・ルール・計算条件・EstimateResultをパラメーターとして受け取り、不整合を拒否し、正規化したEstimateResultのハッシュに結び付く証明を返す。Markdown本文を送る必要はない。

証明は数値整合・指定ルールとの対応・発行元署名を対象とし、ソース網羅性・AI意味判断・為替の真正性・実工数・納期・市場価格・提出者本人性を保証しない。署名対象は構造化結果であり、PDF全体の電子署名ではない。

旧文書証明とは別の契約・方式識別子を使う。信頼済み公開鍵で検証し、入力中の任意の鍵を信頼しない。検証入力・モデル本文を永続保存せず、再送に必要な操作ID・要求指紋・証明等の最小記録を保持する。同一要求は同じ証明を返す。

## 6 公開する情報とWeb保存

公開情報は集計結果、計算条件、ルール版、為替条件、品質の集計・規定コード、証明に限定する。ソース・パス・企業名・案件名・機能名・根拠・判断台帳・自由記述は送らない。詳細数値モデルはMCPだけへ送り、Webへ送らない。未知フィールドは拒否する。

Webは有効な証明と一致する結果だけを保存する。本番は本番の信頼済み証明を要求する。保存確定後にHTTPSの結果URLを返し、閲覧者は通常のGETで開く。ログイン、Web上の再承認、ファイル選択、受付コード、ポーリングは不要とする。

最初の公開完了日時から365日で公開を終了する。閲覧・再送では延長しない。本文・PDF・データの全読取経路で期限を検査し、削除ジョブ未実行でも期限後は返さない。期限切れ本文は定期削除し、再送による復活を防ぐ最小記録を残す。再公開は利用者の新たな希望と確認による別操作とする。

公開URLはログインなしで共有可能であり、本人限定とは表示しない。検索一覧・サイトマップには載せず、検索除外をアクセス制御と説明しない。結果は固定し、再見積で上書きしない。

誤公開への対応として公開停止を提供する。公開操作ごとの管理秘密をローカルで生成し、Webはそのハッシュだけを保持する。管理秘密を公開URL・本文・共有PDF・ログへ含めない。期限終了・公開停止は証明そのものの失効と区別する。

## 7 表示と復旧

チャット・Web・PDFは同じ固定結果を用い、総工数中央値、人日・幅・品質、金額・規模、詳細条件の順で表示する。部分試算の扱いとTEST表示を全媒体で一致させる。WebのPDFも保存結果から生成し、MCP再計算を要求しない。

ローカル状態で承認・要求・証明・登録応答を関連付け、失敗した工程だけ再試行する。同一公開操作・同一要求は同じURL・期限を返す。停止済み・期限切れの再送は復活させない。公開結果を取得できても実ブラウザーの表示確認済みとは扱わない。

## 8 互換と完了条件

旧本人限定データは自動公開せず、旧URL・旧証明の検証可能性を維持する。旧同意を新しい公開へ読み替えない。旧受付・15分表示・30日保存・延長・ファイル選択は新規フローから除去する。

完了条件は、実ChatGPTで開始時一回の製品側同意から、解析・結果カード・PDF・証明・Web保存・結果URLの実表示まで通ること。単体試験、ステージングAPI成功、模擬ホスト表示は別の証拠とする。ローカル・証明・Webを単体で試験でき、サービス停止の影響を分離する。
