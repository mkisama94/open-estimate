## 1. 提案の中心

「先が分かる開始案内」「必要な判断だけをボタンで選択」「結果と次の行動を同時に表示」を、一つの試算体験にする。

標準ルートは **対象確認 → 解析 → 結果** の3段階を見せつつ、通常の利用者判断を **解析開始と送信確認の2回** に整理する。解析中の準備・検査・保存・再計算の呼出しは自動でつなぐ。同じ対象・同じ内容への同意は繰り返さない。対象や送信内容の実質変更時には再確認する。

2回は、本人確認・必要な権限設定が済み、追加の対象指定が不要な場合の製品上の目標。初回のアカウント関連付け、ホストの承認、期限切れの再認証は別途あり得る。「必ず2クリックだけ」とは約束しない。

ソース解析の実行環境は引き続き、対象フォルダーを読み取り、補助CLIを実行できるWork／Codex。Chat上の見た目だけでPCのコードを解析できるとは案内しない。

## 3. 最初に見せる案内

本文解析より前に、以下を一つの開始カードに出す。対象フォルダー名などの私有情報はローカル／ホスト内の表示に留め、遠隔のUI生成ツールへ渡さない。

> **ソースから開発規模と参考工数を試算します。**  
> ① 対象を確認 → ② AIが解析 → ③ 送信内容を確認して結果を表示  
> **ソースコードをOpen Estimateのサーバーへ送信することはありません。一般公開もしません。**  
> Open Estimateに送るのは、確認いただいた数値データと計算に必要な基準情報です。  
> コードを読むAIの処理には、ご利用のCodex／ChatGPTのデータ取扱いが適用され、モデル提供元（OpenAI、Anthropicなど、ご利用中のAIサービスのモデルを提供する事業者）へコードが送られる場合があります。  
> 試算結果は参考値です。現在はTEST基準を使用します。

カードには対象・除外範囲、得られるもの、現在の送信状態、主ボタンを出す。「この対象の解析を始める」と「対象を変更する」を用意し、同意済みの同一対象なら説明を表示して作業を続ける。

短い安心案内は開始時・送信確認時・結果ページに同じ表現で置く。詳細は「データの扱い」で展開する。大切なAI側の取扱いは詳細内だけに隠さない。

「決して外部へ送られない」「完全オフライン」「秘密情報を完全に検出」とは表示しない。OESへの送信禁止と、AIホストの処理、ローカルでの保存を区別する。既存のファイル名による除外を、完全な秘密検出の保証にしない。

## 4. 体験の流れ

| 場面 | 常時見える内容 | 利用者の操作 |
|---|---|---|
| 開始 | 対象、3段階の見通し、データの扱い、TEST参考値であること | 「この対象の解析を始める」 |
| 解析中 | 現在の処理、確認済み／未確認の範囲、外部送信前であること | 必要なら中断。通常は操作不要 |
| 送信確認 | 実際に送る項目、送らない項目、送信先、目的、保持期間、ローカル試算の要約 | 「数値データを送信して試算する」または「送信せず終了」 |
| 完了 | サーバー再計算結果、測定の完全性、TEST表示、本人用URLと期限、次の操作 | 結果を開く、内訳を見る。保存は任意 |
| 再訪 | 保存済み結果、元の計算基準、作成時点、状態 | 元結果を確認。新しい条件での再計算は別結果として扱う |

本人用一時ページを作る経路では、送信確認のボタンを「数値データを送信して、本人用ページを作成」にする。確認文に再計算・一時保存・期限を明示する。再計算と一時ページの作成を一回の具体的な操作として承認する設計変更であり、現在の送信同意を後付けで広げない。

解析が終わった後に「次は何をすればよいか」を自由記述で尋ねない。状態に応じた主ボタンを一つ、取り消し／別の選択を補助ボタンとして示す。書式整理・同じ送信内容の再説明・結果保存先の表示を理由に再承認を求めない。

## 5. Intelligent UI と同意ボタン

**Intelligent UIに適するもの**は、最初の手順図、データの行き先、進捗、結果の要約、CFPから工数への関係、未確認事項の展開。表示は必ず実際の構造化結果から作り、見た目のために割合・所要時間・精度・値を創作しない。

**送信を確定するボタン**は、対応ホストではMCP Apps UI、確実に提供する代替経路では公式Webの確認画面として実装する。MCP Apps UIはプラグインが用意する固定の操作画面で、生成される回答の見せ方とは区別する。公式仕様ではUI resource、`structuredContent`、`tools/call`を組み合わせられる。[OpenAI公式：Add UI to your MCP server](https://developers.openai.com/plugins/build/chatgpt-ui)

ホスト名だけで対応と決めず、UI表示・ツール実行・承認応答・ローカル実行の能力を確認する。Codex／Workで希望どおりの埋め込みボタンが動くかは実機検証対象。表示できない場合も、公式Webのボタンで同じ説明と判断ができるようにする。ホストが提供する選択式確認も利用候補だが、利用可能性を固定的に約束しない。

ホスト独自のツール承認は製品の同意画面と別に残ることがある。UIを付けただけでホスト承認を消せるとは扱わない。[OpenAI公式：Plugin UI reference](https://developers.openai.com/plugins/reference)

### 同意の実装要件

- 同意の記録は、対象run、送信内容のダイジェスト、送信先、操作目的、規約／説明版、確認日時、期限と結び付ける。機密を含む元run IDやソースのhashを遠隔へ公開しない。ローカル識別子と遠隔の不透明な操作IDを分ける。
- 送信内容はローカルで凍結する。画面確認の後で変わった場合、古い同意では送らない。
- サーバーの認証済み承認とローカル側の対象を結び付ける。AIが`user_confirmed: true`を書いたことだけを、人間が押した証拠にしない。初期版は既存のブラウザー同意・照合を再利用する。
- 遠隔で確認カードを生成するために、同意前の数値モデルや私有情報を送らない。ローカル表示または非内容の操作ハンドルを使う。事前通信がある場合は、実際に送る関連付け情報も説明する。
- 二重クリック・応答喪失・再読込は同じ操作へ戻し、二重保存や二重送信を防ぐ。クリック直後は「受付中」、成功応答後にのみ「完了」とする。
- 読取／解析、外部送信と一時表示、長期保存、証明書発行、一般公開は目的を分ける。全項目への包括同意や初期チェック済みの保存・公開を置かない。
- 同意を撤回／拒否したら送信しない。期限・対象変更・アカウント変更を検査する。期限切れのUI状態を権限として再利用しない。

## 6. URLを試算の成果として返す

「試算した」ことと「一般公開した」ことを分け、通常の完了画面に本人用URLを置く。URL自体は計算基盤が返したものを表示し、AIがIDからURLを推測しない。

| 種類 | 役割 | 推奨する扱い |
|---|---|---|
| 本人用一時URL | 今回の試算をブラウザーで確認 | 最初の実装対象。本人認証必須、既存と同じ15分から開始し、期限日時を常時表示 |
| 保存した本人用URL | 日を改めて結果を確認 | 次段階。「この試算を保存」で個別に選択。保存対象・保持期限・削除方法を確定してから提供 |
| 一般公開URL | 相手に見せる、署名記録を検証する | 独立した発行・公開手順。本人用URLの作成だけでは発行しない |

本人用一時URLを「後からいつでも見られる保存済み結果」とは呼ばない。保存の初期提案は30日・延長または削除を本人が選択する方式だが、これは製品判断として未確定。保存同意前に期間を曖昧にして実装しない。

通常試算用に、数値モデル・基準情報・状態コードのみを扱う専用の本人用結果契約を作る。現行の証明書候補・公開用説明を必須にせず、既存の本人認証、送信前承認、再計算、期限管理の仕組みを再利用する。

送信項目は機械検査する許可リストに限定する。モデル内の数値、匿名の識別子、表示通貨、配布スキルの版と整合性情報、測定規則の版など、実際の契約を確認画面と一致させる。ソース本文、ファイルパス、機能名、説明、根拠、判断台帳、対象ソースhashを混入させない。ルール／スキルのhashと対象ソースのhashは明確に区別する。

リンク先は所有者の認証・認可を毎回確認し、URLを知るだけでは読めないようにする。削除、失効、他人のアクセス、結果は完成したがURL作成だけ失敗した場合をそれぞれ扱う。

## 7. 結果の伝え方と失敗時の回復

完了画面は「試算処理の完了」と「測定対象の確認状況」を別に示す。PARTIALでも再計算が成功することはあるため、「試算完了・一部未確認」のように併記する。未算出を0にしない。

主に表示するものは、機能規模、参考工数、単位と基準、未確認範囲、本人用リンク。金額換算がTESTまたは算出不可なら、その条件を数字の近くに置く。「確定見積」「監査済み」「実工数の保証」とは呼ばない。

| 状態 | 表示と回復 |
|---|---|
| ローカル解析の権限不足 | 解析を始めず、不足する条件と再開手順を示す |
| 送信拒否／中断 | ローカル試算を表示。「未送信」を維持する |
| ネットワーク障害 | 「再計算未完了」。既存runを保持し、同じ操作の状態確認から再開 |
| 再計算成功・URL作成失敗 | 数値結果は表示。「本人用ページの作成のみ再試行」を出す |
| 結果不一致 | ローカル値と受信値を保持。確認が済むまで一致・確定と表示しない |
| 為替が未取得 | 有効なCFP・時間等を表示し、換算できない通貨だけ未算出にする |
| 期限切れ | 失効した理由と作成日時を表示。新たな送信が必要な再作成は同意から再開 |
| 保存失敗 | 「試算完了・保存未完了」。保存済みと誤表示しない |

進捗は「対象を確認」「機能を整理」「計数を検査」など処理段階で示す。読取件数に母数がある場合のみ件数を表示し、推定の百分率や残り時間を事実として表示しない。

## 9. 受入条件

1. 初回のソース本文読取より前に、手順・OESへの非送信・AIホスト側の扱いが表示される。
2. 同一対象への有効な既存同意で、重複の文章入力を求めない。
3. 対応ホストでは、開始・送信確認の両方を自由記述なしで操作できる。初回認証とホスト承認の追加回数も別に記録する。
4. ボタン表示だけでなく、クリック→対象に結び付いた承認→実処理→結果が実機で確認できる。
5. 同意前の描画、通常送信、拒否、エラー、ログの各経路に、合成canaryのソース本文・名称・パス・根拠・ソースhashが含まれない。
6. 送信内容変更・期限切れ・別所有者・偽造同意・二重クリック・応答喪失を検査できる。
7. 試算と一時ページ作成が成功した場合、実際に返された本人用URLと期限が完了カードに表示される。
8. 本人用URLは本人のみ閲覧でき、別アカウント・ログアウト・期限切れでは内容を返さない。
9. PARTIAL、TEST、未算出、保存失敗を成功表示で覆い隠さない。
10. UI非対応時にもWebのボタンまたは利用可能なホストの確認機能で継続でき、表示用UIだけの状態を同意として扱わない。
11. ソース解析、通常試算、本人用表示の途中で、署名・証明書・一般公開が実行されない。
12. checkout、配布物、サーバー登録、本番反映、ホスト実機の結果を分けて報告する。

製品上の改善指標は、自由記述による同意回数、重複確認回数、完了時URL提示率、初回／再利用時の離脱箇所、失敗時の再開率。実測前に削減率や短縮時間を宣伝しない。計測にもソースや私有名称を収集しない。
