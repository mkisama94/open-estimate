## 1. 製品の目的と仕様の優先順位

Open Estimateの標準体験は、**許可されたソースを解析し、数値モデルを再計算して、本人がWebページで見積結果を確認できるところまで案内すること**とする。Web表示は製品価値の中核であり、利用者が「Webで表示して」と追加依頼したときだけ提供する機能にはしない。

開始時から「見積 → 本人用Web表示 → 必要に応じて保存・計算証明書の発行と公開」という全体像を伝える。計算証明書は、発行元が再計算結果に電子署名し、第三者が署名や公開・失効状態を確認するための機能である。現在使える機能と、未提供・停止中の機能を区別して表示する。

本書は、[旧改善提案](PLUGIN-EXPERIENCE-IMPROVEMENT-PROPOSAL.md)、[製品構成](PRODUCT-ARCHITECTURE.md)、既存スキル・導入文書のうち、標準経路、完了条件、UI、機能案内に関する記述に優先する。旧提案の「検討中」事項は本書で定めた範囲について解消する。計数・換算の規則と[計算証明書仕様](SIGNED-CALCULATION-CERTIFICATE-SPEC.md)の署名対象・証明範囲・発行条件は維持する。

| 要件ID | 正式な要件 |
|---|---|
| WEB-01 | 通常の見積依頼には、本人用Web表示までの案内と実行を含める。追加のWeb依頼を前提にしない。 |
| WEB-02 | 通常成功は、実際の作成応答に含まれる本人用結果URLと期限を受領し、利用者に開く操作を提示した状態とする。再計算の成功だけでは満たさない。 |
| WEB-03 | URLを作れないときは未完了の段階、理由、次の操作を示す。「Web表示用URLは未作成です」だけで終了しない。 |
| UI-01 | 解析前に、サービスの全体像、データの扱い、今回使える機能、次の操作を表示する。 |
| UI-02 | 対応環境では実際に操作できるIntelligent UIを使い、未対応・表示失敗時も同じ案内と操作経路を提供する。 |
| TRUST-01 | 本人用Web表示、保存、サーバー再計算、電子署名、一般公開を別の状態として説明する。 |

### 1.1 今回の問題をどう解消するか

0.8.1のスキルは`evaluate_model`で再計算し、Webプレビューは「希望する場合」に別経路へ進む。既存の`show_preview_confirmation`も、その別経路が受付IDを返した後に初めて使われる。このため、Web生成もUI表示も呼ばない通常終了が成立していた。

改善では、スキルの文章だけでなく、処理の状態、ツール応答、CLIの再開情報、UI呼出し、受入試験のすべてを本書の完了条件に合わせる。`evaluate_model`は再計算部品として残してよいが、その成功をプラグイン全体の成功として扱わない。

## 2. 標準の利用経路

利用者に見せる主要な流れは **対象を確認 → 解析 → Webで結果を確認** の3段階とする。内部の準備・検査・再計算・ページ生成はこの流れに統合する。

1. ソース本文を読む前に全体像を表示し、ローカル読取・補助CLI・測定ルール・本人用Web表示の利用可否を確認する。対象の構成確認は既存の読取境界に従う。
2. 対象・範囲・除外・上限を提示し、**「この範囲で解析を開始」**でソース読取の同意を得る。範囲を変更する選択肢も設ける。
3. ローカルで解析・検査し、試算値、TEST、COMPLETE／PARTIAL、未確認事項を示す。この時点は「ローカル解析完了」であり、標準体験の完了ではない。
4. 送信する項目、送信先、再計算、15分間の本人限定Web表示をまとめて説明する。**「数値データを送信してWebで結果を見る」**を主操作とし、**「送信せずローカル結果で終了」**も用意する。
5. 同意と必要な本人確認が成立した後に、送信・再計算・本人用ページ生成を連続して進める。同じ内容について「Webページも作りますか」と再確認しない。
6. 作成成功後、チャットとUIに本人用URL、期限、**「Webで見積結果を見る」**を表示する。確認用ブラウザー画面は、準備完了後に本人用結果へ遷移できるようにする。
7. 結果ページで、30日保存、保存の延長・削除、計算証明書の説明と発行・公開への導線を示す。保存・発行・公開を選ばなくても本人用Web結果を閲覧できる。

通常の製品上の同意は「対象読取」と「送信・再計算・本人用Web表示」の2つに整理する。ログイン、ホストが要求する権限承認、関連付け、期限切れ再認証は別に必要となり得るため「必ず2クリック」とは表現しない。チャットとブラウザーで同じ送信同意を二重に要求せず、ブラウザーで確定する場合のチャット側ボタンは「送信内容を確認してWeb表示へ」とする。

### 2.1 完了と例外

| 状態 | 利用者に示す内容と必須操作 | 標準体験の成功か |
|---|---|---|
| 解析中・送信確認待ち | 現在の段階、次に必要な判断 | いいえ |
| 再計算済み・Web作成中 | 「再計算済み。Webページを準備しています」 | いいえ |
| 本人用Web結果作成済み | 返却されたURL・期限・開くボタン。未署名／公開状態も表示 | はい |
| 利用者がローカル終了を選択 | ローカル結果と保存先、Webを作らなかった選択、後で再開する方法 | 利用者の選択による終了。標準成功とは別記録 |
| Web未対応・停止・失敗 | 失敗した段階、判明した原因、再試行／設定確認／ローカル終了など実行可能な次の操作 | いいえ |
| 同意待ち・認証待ちで中断 | 待っている操作と再開導線。完了扱いにしない | いいえ |

URLが返ったことと、利用者がページを開いたことは別に記録する。開いた証拠がない場合に「Webに表示しました」と断定せず「本人用Webページを作成しました」と伝える。確認URL、管理一覧URL、ローカルファイルリンクを結果URLの代わりに数えない。URLやIDを推測して作らない。

## 3. 最初に伝える価値と安心の説明

初回メッセージと開始カードは、環境調査の長い報告より先に、以下の内容を短く提示する。後続の見積でも、現在の段階とWebまで進むことは省略しない。

> Open Estimateは、許可いただいたソースをもとに参考工数を見積もり、本人だけが見られるWebページで結果を確認できるサービスです。
>
> 流れは「対象の確認 → 解析 → 数値データの送信確認 → Webで結果を見る」です。結果は15分間表示でき、希望すれば30日間保存できます。さらに、計算結果への電子署名と公開により、第三者が署名・発行元・現在の公開／失効状態を確認できる計算証明書の仕組みがあります。今回の環境で使える機能をあわせて表示します。
>
> ソースコードはOpen Estimateのサーバーへ送信されず、一般公開もされません。AIによる解析では、ご利用中のAIサービスがソースコードをモデル提供元（OpenAI、Anthropicなど、利用中のAIサービスのモデル提供元のこと）へ送信・処理する場合があります。Open Estimateへのデータ送信とは別の扱いです。

利用可否の確認前は「今回利用できるか確認中」と表示する。Webが使えないと判明した場合は、解析を長時間進める前に理由と選択肢を示す。例：「この接続では本人用Web表示が利用できません。接続を直すか、今回はローカル試算のみで進めるか選べます」。応答がない場合を「利用可能」としない。

利用可否は接続先の実応答と契約の互換性で確認し、ツール名の検出やプラグインの版だけから推定しない。サーバーはWeb表示・保存・発行・公開それぞれの有効状態と必要な準備の不足を区別して返す。本人確認が必要な場合は「ログイン後に利用可能」と表示できるが、ログインを省略しない。確認のために見積データを送信したり、仮の結果ページを作ったりしない。

開始カードと結果カードには、常に次の機能一覧を見える形で置く。使えない項目を消して製品の全体像を隠さない。ただし、利用できない操作ボタンは無効化し、理由と必要な次の操作を添える。

| 機能 | 価値の説明 | 表示する利用可否・状態 |
|---|---|---|
| 本人用Web表示 | 数値と注意点を、本人だけが見られるページで確認 | 確認中／利用可能／準備中／作成済み／利用不可／期限切れ |
| 30日保存・管理 | 後日見返し、期限の延長や削除を行う | 利用可能／未保存／保存済み・期限／利用不可 |
| 計算証明書・公開 | 発行元の電子署名を第三者が検証し、固定結果と現在の状態を確認 | 利用可能／未発行／発行済み／停止中／この環境では未提供 |

未提供の証明書機能を、今回の見積で直ちに使える機能として宣伝しない。「未署名」のラベルだけで説明を終えず、何のための機能か、使える場合はどこから進めるかまで伝える。

## 4. Intelligent UIの正式要件

本書のIntelligent UIは、ホスト内の対話カードと、必要な場合の公式Web画面が、実際の処理状態と利用可否に応じて案内・ボタンを変えるUIを指す。モック、長文のMarkdown、ホスト標準の選択肢だけで「Intelligent UI実装完了」としない。

### 4.1 必須の画面と表示タイミング

| 画面 | 表示タイミング・必須内容 | 主な操作 |
|---|---|---|
| 開始・全体像 | 見積依頼直後、本文解析前。Webまでの流れ、機能一覧、プライバシー、利用可否 | 対象範囲の確認へ進む |
| 対象確認 | 構成確認後。実際の範囲、除外、上限。ローカルの対象情報はホスト側で表示 | この範囲で解析を開始／範囲を変更 |
| 進捗 | 解析・検査・再計算・Web作成の段階が変わるとき。確認済み／未確認を区別 | 中断時の再開。根拠のない進捗率や残り時間は表示しない |
| 送信確認 | ローカル検査後。送信項目、送信先、15分表示、品質状態と注意点 | 数値データを送信してWebで結果を見る／送信せず終了 |
| 結果 | Web作成成功時。主要な試算値、TEST／PARTIAL、本人用URLと期限、機能一覧 | Webで見積結果を見る。Web側で30日保存／証明書の説明へ |
| 中断・失敗 | どの段階でも。失敗段階、原因、保持されている結果、次の操作 | 同じ結果で再開／認証をやり直す／ローカル結果を確認 |

開始・送信確認・結果・失敗の各段階で、スキルは対応する表示処理を必ず実行する。利用者がUIを要求したかどうかで分岐しない。表示処理は再計算や保存の処理と分離し、カードの再描画で再送信・再保存しない。

### 4.2 対応環境と代替経路

| 環境 | 必須の体験 | 受入時の区分 |
|---|---|---|
| 埋込UIに対応 | 実カードを表示。クリックによる状態遷移と結果URLを確認 | Intelligent UI対応 |
| 埋込UIが未対応・表示失敗 | チャットで同じ全体像と状態を示し、ホスト標準の選択式確認と公式Web画面のボタンを使用。結果URLは必ずチャットにも表示 | 代替経路で動作。埋込UI対応とは記載しない |
| ローカル処理不可 | 全体像と必要な実行環境を説明し、解析開始不可を明示 | 見積非対応。Web画面だけでローカル解析できると説明しない |

ホスト名だけで対応を決めず、実際のUI能力と表示結果に基づいて分岐する。表示失敗を検知できない環境でも、同じ応答に短い文字案内と実リンクを併記する。ボタンを使えない環境でのみ文字による意思確認を代替として認める。未対応だからとWeb案内や証明書の説明まで省略しない。

MCP AppsのUI resourceを表示ツールへ関連付け、構造化した処理結果から描画する。UIの初期化、操作、失敗、再表示を試験対象にする。破壊的なUI変更ではresource URIを更新し、古いキャッシュとの混在を防ぐ。この接続方針は[OpenAI公式UI実装資料](https://developers.openai.com/plugins/build/chatgpt-ui)に基づく。個々のWork／Codex環境で表示可能かは実機受入で判定する。

### 4.3 操作とデータの境界

- 送信前の開始カードは汎用の案内と機能状態だけで表示できること。UIを出すためにソース、対象名・パス、根拠、判断台帳、未同意の数値モデルをリモートへ渡さない。
- 対象範囲の詳細とその同意はローカル／ホスト側に保持する。ホストにローカル操作連携がない場合は、カードの隣に範囲を示し、ホスト標準の選択式確認で受ける。リモートのカードにPCファイル操作権限を与えない。
- UIの表示、選択肢の初期選択、ログイン成功を同意と扱わない。対象・範囲の版と送信内容・期限に対応する、明示的な確定操作を記録する。
- サーバー上の閲覧・保存・発行・公開は、サーバーが認証と対象への権限を検証する。モデルの説明文やUIの状態だけで許可しない。
- 二重クリック、画面再読込、チャットの再開で同じ見積を重複生成しない。進行中は操作状態を明示し、古いカードから別の結果へ作用させない。
- キーボード操作、フォーカス、読み上げ名を用意する。状態やTEST／PARTIALは色だけに頼らない。狭いカードでも主操作・期限・注意点を見失わない配置にする。

## 5. データ送信とWeb結果の契約

通常見積に、公開候補の説明文や証明書発行用の入力を必須にしない。数値モデルから本人用Web結果を作る専用の契約を用意する。既存の証明書候補経路を使いながら「数値だけを送信する」と説明することは禁止する。

標準経路の許可項目は、数値モデル、表示通貨、スキルID・版・配布物の整合性ハッシュ、測定ルール参照版、および当該操作に必要な関連付け情報とする。関連付け情報は認証済み所有者にひも付く不透明な操作ID等に限定し、プロジェクト識別情報を埋め込まない。ソース本文・抜粋・ファイル名・パス・対象名・説明自由文・ローカル根拠・判断台帳は通常送信しない。送信許可項目をSchemaと試験で固定する。

Webページには受信・再計算できた数値と状態だけを表示する。サーバーへ送らない根拠や未確認事項の詳細はローカルで参照し、Webで確認できる範囲を明示する。TEST、PARTIAL等の品質状態と、受信モデルに含まれる暫定計数を落とさない。ローカル結果と再計算結果が不一致なら通常成功にせず、照合エラーとして扱う。

本人限定の一時表示は15分、明示的な保存は30日とする。期間の起点と実際の失効時刻はサーバー応答に従って画面に明示する。保存後の期限は一時ページと独立する。保存の延長・削除も本人の操作として提供する。期限切れや削除後を長期閲覧可能なURLとして案内しない。

### 5.1 状態と応答に必要な情報

以下は新経路が保持・返却すべき論理項目であり、現行APIに既に存在するフィールド名を表すものではない。

| 情報 | 用途と要件 |
|---|---|
| 操作ID、結果の版・hash、再開参照 | 同じローカルrun・承認対象・再計算結果・Webページを対応させる |
| 現在の段階 | 同意待ち／再計算中／Web作成中／Web作成済み／失敗／利用者による終了を区別 |
| 再計算結果と品質状態 | CFP、工数、金額・換算情報、TEST、COMPLETE／PARTIAL、照合状態 |
| 本人用結果URL・期限 | 作成済みの応答でのみ返す。確認ページURLとは別項目 |
| 保存・署名・公開の状態 | 一時表示、保存済み、未署名、発行済み、未公開等を分離 |
| 機能の利用可否と理由 | 未提供、設定不足、停止中、認証必要、照会失敗を区別。未確認を利用可能にしない |
| 失敗段階、安定したエラー識別子、次の操作 | 説明文だけに頼らず、同じ操作の安全な再開へつなぐ |

ローカル側の完了判定は、再計算結果だけでなくWeb作成状態を検査する。`WEB_READY`相当の状態がない場合は、未完了の次操作を返す。スキルはその状態を利用者へ伝え、通常完了の文面へ進まない。

## 6. 「証明される」という価値の伝え方

Webで見えること自体を、電子署名による証明とは呼ばない。開始カード、結果カード、Webページで同じ区別を使う。

| 状態 | 許される説明 | 許されない説明 |
|---|---|---|
| サーバー再計算済み | 「受領した数値モデルをサーバーで検査・再計算しました」 | ソース監査済み、工数の正しさが証明済み |
| 本人用Web表示 | 「本人だけが結果を閲覧できます。計算証明書は未発行です」 | Web掲載だけを根拠に電子署名済みと表示 |
| 署名付き計算証明書 | 実際の署名・検証結果に基づき、発行元と固定した計算結果の改変有無、公開・失効状態を説明 | ソースの真正性・網羅性、AIの意味解釈、実工数・価格を保証 |

計算証明書の説明は、発行元が **AI Orchestration Inc.** であること、ソース解析に使うAIサービスとは役割が違うこと、独立した第三者によるソース監査ではないことを明示する。利用者がOpenAI等を信頼していることを、Open Estimateの運営者への信頼と同一視しない。

証明書機能が利用可能な場合、結果ページに**「計算証明書と公開内容を確認」**を表示する。確認画面で署名対象、公開する情報、証明範囲、TEST／PARTIALを説明し、発行と一般公開の意思をそれぞれ明示的に確認する。既存の証明書初版では両方への同意が必要であり、片方だけで実行しない。通常のWeb表示や保存への同意を流用しない。

未提供・停止中の場合も説明は表示し、実行操作を無効化する。Web表示の改善完了と、証明書の本番提供完了を別に判定する。証明書仕様に残る公開前提を解消したものとは扱わない。

## 7. 失敗・再開・既存結果の扱い

| 場面 | 必須動作 |
|---|---|
| 解析前にWeb不可が判明 | 理由を示し、接続・設定の確認か、明示的なローカル試算の選択を案内 |
| 再計算成功後にWeb作成だけ失敗 | 再計算結果を保持。「Web作成が未完了」とし、同じ結果から再開。理由不明なら未特定と表示 |
| 同意待ち・ログイン切れ | 承認画面への導線を提示。認証や新たな同意が必要な操作は、その完了後に再開 |
| PARTIALだが検査に合格 | PARTIALと未確認の範囲を明示してWeb作成へ進む。PARTIALだけを理由に案内を省略しない |
| モデル検査・照合の失敗 | 誤った結果ページを作らず、修正箇所と再検査を案内。未算出を0と表示しない |
| UI表示失敗 | 同じ結果・状態を使い、チャットの案内と公式Web操作へ切り替え。解析や送信を重ねて実行しない |
| 一時URLの期限切れ | 失効を表示。保存済みなら保存先、未保存なら残っているローカル結果から新しい承認・作成手順を案内 |
| 0.8.1などの再計算だけで終わった結果 | 既存runを検査してWeb表示を必ず提案。旧来の数値送信同意だけではWeb保持に同意したと扱わず、不足する確認を取る |

一時的な通信失敗では同じ操作IDで再試行する。現行preview経路の復旧では同じ`submission_id`の`resume-preview`を使う。新契約でも同等の重複防止と再開機構を必須とする。期限切れで新操作が必要な場合は旧操作との関係を記録し、元runを上書きしない。無制限に再試行せず、継続できない場合は理由と具体的な再開操作を残す。

## 8. 実装対象とリリース条件

Web統合とIntelligent UIは、どちらも今回の体験改善の必須項目とする。UIを「余裕があれば行う後続装飾」として完了判定から外さない。

| 対象 | 必要な変更 |
|---|---|
| スキル・プラグインの案内 | 通常依頼の目標、開始説明、各段階の表示呼出し、Web完了判定、失敗時の次操作、証明書の説明を更新 |
| ローカル補助CLI | 通常の数値契約での送信・Web作成、同意対象との対応、結果照合、再開・重複防止を統合 |
| リモートMCP | 利用可能機能の取得、通常結果のWeb生成につなぐ処理、状態応答、開始・結果・失敗を含む表示ツールを提供 |
| Intelligent UI | §4の画面と操作、状態反映、表示失敗時の代替、アクセシビリティを実装 |
| Web・認証・保存 | 通常の数値モデルから本人限定表示。15分表示、30日保存、証明書導線と提供状態の明示 |
| 配布・本番設定 | Skill／CLI／MCP／Webの版と契約、ルール登録、DB・設定・ルート・UI resourceを揃えて確認 |

実装時は新しい配布版を採番し、スキルhash・受信側登録・ローカルmarketplaceを整合させる。公開済み0.8.1の成果物を同版のまま変更して受入を行わない。WebとMCPのデプロイ、DB更新、機能有効化、プラグイン更新は別々に確認し、いずれかの成功を全体の成功に読み替えない。

対象ホストごとに、製品名・版・実行環境・埋込UI能力・代替経路・試験日を受入記録へ残す。ローカルテスト、サーバー疎通、実ホストUI、本人のログインを通したWeb閲覧の証跡を分ける。対応をうたう環境での確認前に、体験改善を「本番完了」としない。

## 9. 受入条件

### 結果レポートの提示順（0.9.1）

ChatGPT本文でも冒頭を「総工数の目安：○時間（中央値）」のMarkdown見出しとし、直下に人日・TEST/PARTIAL、保存済み結果なら日付と再解析の有無、参考幅、送信・Web状態、詳細の順に表示する。中央値を表内だけに埋め込まない。通常成功、送信せず終了、過去結果の再表示、Web作成失敗の全分岐に適用する。カードの成否に依存しない。値がない場合は未算出と表示する。この表示のために送信同意を追加・代行しない。

見積結果は頭括式とし、最初に総工数の中央値を最も大きく表示する。人日とp25〜p75の参考工数の幅を続け、その後に工数・参考金額の表、機能規模と内訳、根拠・未確認事項、保存と証明書の説明を配置する。チャットも総工数の結論を一文目に置き、実結果URLを直後に案内する。CFPや処理完了の経緯を主見出しにしない。

TEST参考値とPARTIALの状態は先頭に短く表示し、詳細な制約は後段で説明する。未算出を0で代替しない。人日は総作業量であり経過日数・納期ではない。表示上の優先順位だけを変更し、計算値や同意条件は変更しない。一時結果と保存済み結果の両方に適用する。

| ID | 条件・入力 | 合格条件 |
|---|---|---|
| AC-01 | 新規チャットで「このプロジェクトを見積もって」とだけ依頼 | 本文解析前に、Web表示・保存・計算証明書までの全体像、今回の利用可否、プライバシー説明が現れる |
| AC-02 | 埋込UI対応ホスト | 開始・送信確認・結果の実カードが表示され、ボタン操作で正しい処理へ進む。利用者の自由記述「進めて」は不要 |
| AC-03 | 標準送信に同意 | 追加のWeb依頼なしで再計算と本人用Web作成が実行され、実URL・期限・開くボタンがチャットとUIに返る |
| AC-04 | AC-03の本人用URLを実ブラウザーで開く | ログインした所有者が対応する見積を閲覧でき、数値・TEST／PARTIAL・未署名状態が一致。別所有者・未認証アクセスは内容を取得できない |
| AC-05 | 送信せず終了を選択 | 送信・Web作成を実行しない。本人の選択によるローカル終了と、後でWeb表示へ進む方法を記録・表示 |
| AC-06 | Web停止・設定不足・機能照会失敗 | 解析前に案内。利用可能と誤表示せず、選択式の次操作を提示 |
| AC-07 | 再計算成功後にWeb生成を失敗させる | 通常完了にしない。原因と再開操作を表示し、同じ結果で復旧。重複送信や結果の上書きが起きない |
| AC-08 | 検査合格のPARTIAL結果 | Web作成と案内を省略せず、暫定値と制約を表示。未確認を完全検証済みと見せない |
| AC-09 | 埋込UI未対応、初期化失敗、描画失敗 | 全体像がチャットに残り、選択式確認・公式Webボタン・実結果リンクで完遂。埋込UI成功として記録しない |
| AC-10 | 旧来の再計算だけの結果を再開 | 再解析を強制せずWeb表示を案内。Web保持の追加確認前に作成しない |
| AC-11 | 保存・証明書を選ばずWeb閲覧 | 本人用表示は成功。保存、署名、公開は行われず、各機能の価値と現在の状態が見える |
| AC-12 | 証明書の未提供時／提供時 | 未提供時も説明と理由が見える。提供時は明示的な発行・公開確認へ進み、実際の証明書と検証状態に基づいて表示 |
| AC-13 | 未承認、二重クリック、期限切れ、古いカード、別所有者 | 未承認の実行や重複生成、別結果への操作、他人の結果表示を防ぐ |
| AC-14 | ソース・パス・根拠に識別可能な試験文字列を入れる | リモートへ送るUI初期化・表示ツール・MCPの情報、Web、サーバー診断ログへその情報が出ない。ホスト内の対象確認表示とAIによる解析処理とは区別して検査 |
| AC-15 | 15分の失効、30日保存・延長・削除 | 実期限に従って表示・アクセスが変化し、保存URLと一時URLを混同しない |
| AC-16 | 入力不正、結果不一致、為替未取得 | 不正・不一致を正常完了にしない。為替未取得は対応する通貨表示の制限を明示し、架空の値を補わない |

標準成功の受入では、対象の同意から実ブラウザーでの本人用結果閲覧までを通しで記録する。単体テストの成功、JSONにURL項目があること、UIの静止画、既存の確認リンクカードだけではAC-02〜04の代わりにならない。

全受入シナリオで機能全体の案内があり、標準経路の送信同意・モデル検査・結果照合が成立し、Webが利用可能なシナリオでWeb作成処理まで進むことを確認する。利用者による拒否、検査エラー、環境障害は別集計とする。「URL未作成」とだけ報告して終了するケースが1件でも残る場合、今回の改善は未達と判定する。
