# Open Estimate 0.10.0（ローカル実行対応ホスト向け）

標準フローは「対象範囲の確認 → 解析 → チャット内プレビューとPDF → 一度の掲載同意 → 本人限定Web結果（30日保存）」。送信せず終了する場合もプレビューとPDFを利用できます。

[設計と操作](implementation/ESTIMATE-PREVIEW-PUBLICATION.md) / [受入記録と外部作業](implementation/ESTIMATE-PREVIEW-PUBLICATION-ACCEPTANCE.md)

## 必要な環境

Node.js 24以上と、対象フォルダーを読み取り補助CLIを実行できるホストが必要です。配布物はローカル表示用stdio MCPと、正規Open Estimateの認証済み掲載用remote MCPを登録します。対応ホストではIntelligent UIの結果カードとPDF取得を使用し、非対応時はチャット本文・PDF・標準の確認操作を使います。ローカル接続ができないweb/mobile環境で、フォルダーパスだけを渡して解析することはできません。

## 利用手順

1. サービスの一般的な利用可否とローカル実行条件を確認する。この段階で見積データを送信しない。
2. 本文を開かずに構成と容量を走査し、計測対象・補助資料・取得対象外を提示する。読取同意後に固定した範囲を取得する。
3. 取得不足を先に判定してから解析し、結果をローカルへ保存する。
4. 保存済み結果からチャット内プレビューと日本語PDFを生成する。主要ソース不足時は全体未算出と部分試算を分ける。
5. 掲載する数値・品質・固定条件、正規サービスへの送信、本人限定30日保存に一度だけ同意する。ソース・対象パス・根拠本文・判断台帳、一般公開・証明書発行を含めない。
6. 認証済みpublish_estimateが同じ結果を検査して保存し、結果URLと期限を返す。未認証なら必要なログインだけを行い同じ操作に戻る。
7. 保存一覧から閲覧・延長・削除する。通信に失敗しても結果とPDFは残り、再解析や同じ掲載条件への再同意なしで再試行できる。

認証情報や秘密値をチャット・CLI引数に貼らないでください。所有者は署名検証した認証情報から決まり、クライアント指定owner IDで切り替わりません。

## 取得制約

1回100 MiB、1ファイル2 MiB。計測対象を優先します。100 MiBを超える対象は同じ合意範囲で分割取得し、一つのmanifestで重複・欠落・変更を検査します。対象外と合意したファイルは本文を読まずコピーしません。秘密・依存関係などの保護除外は維持します。

## 旧版からの移行

旧prepare-estimate/preview-estimate/resume-estimateと、再計算だけのevaluate_model・Web確認カードは通常フローから削除しました。未送信の旧受付はmigrate-estimateで保存済みrunから新しいプレビューへ移行します。旧受付から自動送信しません。既存の保存結果と発行済み旧一時URLはそれぞれの期限まで維持します。証明書系の準備経路は通常見積と分離し、発行・一般公開を有効にしていません。

## 配布と確認状態

npm run build、npm run plugin:pack、npm run plugin:smokeでローカル配布物を生成・検査します。新しい開発版番号は0.10.0です。カタログの公開履歴をローカル実装だけで更新しません。

本番には掲載用OAuth audience・scope・許可clientとD1移行が必要です。ローカルの試験成功は実ChatGPTや本番の受入完了を意味しません。最新の状態は上記受入記録で確認してください。
